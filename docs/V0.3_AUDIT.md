# Audit initial — mission v0.3.0

Date : 31 octobre 2026. Révision initiale locale : `5da26be`, package `0.2.0`, arbre Git propre. Aucun AGENTS.md trouvé dans le dépôt. Sources, spécification initiale, CODE_WIKI, audits historiques, rapports v0.0/v0.1/v0.2, workflows et historique examinés avant les changements.

Référence exécutée avant modification : 49 tests sur 5 fichiers réussis ; ESLint, TypeScript et build de production réussis. L’ancien audit du 27 octobre précédait ces corrections et ne devait pas être repris comme état présent.

## Architecture existante

React/TypeScript/Vite, Zustand pour le document et l’interface, Zod pour la validation. `KineoDocument` est un alias de `KineoV3` ; plus de migration concurrente entre deux modèles. Rendu canvas et export utilisent `planarScene`. Le graphe dérive des corps et liaisons, sans résoudre leur géométrie.

Solides : position optionnelle, rotation scalaire en **radians** autour de Z, indicateur `isFixed`. Les points de géométrie et `anchors.onClassA/B` sont locaux au solide propriétaire. `liaison.position` est une position d’annotation globale ; le quaternion décrit l’orientation du symbole. Les DOF historiques sont des métadonnées, pas un moteur d’animation. Les classes parentées n’avaient pas de composition de transformations dans le rendu.

## Défauts et lacunes identifiés

- `Nouveau` créait correctement un JSON vide, mais `addClass` utilisait `(length − 1) % palette.length` : première couleur `undefined`, rejetée par validation.
- Aucun bouton de création ou de désignation du bâti ; une liaison de la palette exigeait pourtant un bâti.
- Pas d’autosauvegarde, restauration ou événement beforeunload.
- Aucune formulation de contraintes, jacobienne, analyse de mobilité ou simulation réelle.
- Sept types graphiques ; leurs degrés de liberté étaient spatiaux pour plusieurs types. Le pas de l’hélicoïdale est absent.
- Le contrôle de désalignement exigeait la coïncidence de tous les ancrages, ce qui ne convient pas au déplacement autorisé d’une glissière.
- Effet d’ajustement initial annulable sous StrictMode avant son exécution.

Les correctifs et les limites réellement livrés sont décrits dans les documents v0.3, sans réécriture de l’éditeur opérationnel.
