# Kineo v0.2 — Graph & Persistence

## Goal and compatibility

v0.2 builds on the tagged v0.1.0 editor with an interactive mechanical connectivity
graph, synchronized Graph/Split views, unsaved-document protection, and standalone
SVG/PNG exports. The canonical JSON v3.0 document remains the sole persistent model.
No graph layout or other v0.2-only UI state is written into JSON, and no new JSON
fields are required.

The v0.1.0 baseline remains compatible: `jointDefinitions` continues to be a
catalogue of joint templates, while `liaisons` are the actual joint instances.
Existing v3.0 fields and extension properties remain handled by the established
passthrough schema and clone-based conversion path.

## Mechanical graph

`src/model/mechanicalGraph.ts` derives a deterministic undirected multigraph:

- Each `classesEquivalence` entry becomes one graph node, preserving its body ID,
  name, and ground designation.
- Each `liaisons` entry becomes one edge with the liaison ID, type, name, and its
  `classA` / `classB` endpoint IDs.
- `jointDefinitions`, geometry, and `parentId` relationships do not create edges.
- Multiple liaison instances between the same pair of bodies remain distinct
  parallel edges. Unknown endpoints and self-connections are rejected rather than
  repaired or represented as fictitious nodes.
- The model provides adjacency and node/edge/neighbor lookup, connected components,
  isolated and fixed node IDs, parallel-connection groups, cycle edge sets, and
  summary counts. The independent graph cycle rank is `E - V + C`.

The graph is derived from the current document and is not mutated back into it.
`src/model/graphLayout.ts` assigns a deterministic transient position to each node
and separates disconnected components. `MechanicalGraphView` displays nodes and
liaison edges, component boundaries, labels, fixed/isolated cues, and topology
statistics. Users can select nodes or edges, zoom, pan, and fit the graph.

Graph node selection maps to the existing body selection; edge selection maps to
joint selection. The sidebar, inspector, 2D canvas, Graph View, and Split View all
use the same Zustand document and selected-entity state. A graph cycle represents
connectivity only, not a physically closed mechanism or a solved constraint set.

## Split View and persistence lifecycle

Split View places the existing 2D canvas alongside the graph. It does not duplicate
the document or create a separate editing model. View mode, graph positions, camera,
selection, grid visibility, and snapping are interface state and are not serialized.

The store tracks a JSON snapshot of the last saved, newly created, or imported
document. Dirty state compares the current canonical document to that snapshot, so
editing away from and undoing back to the saved state updates the indicator
correctly. Saving JSON marks the current snapshot saved. A valid import or new
document establishes a new clean baseline.

Opening another document or creating a new one prompts before replacing dirty
changes. Declining keeps the active document; accepting replaces it. JSON imports
are parsed and checked against the v3.0 schema and reference-integrity validator
before the active store document is replaced. Errors are surfaced in the header.

## Visual exports

`src/model/export2d.ts` produces a standalone SVG from the canonical 2D geometry:

- Local points are transformed using the owning body's planar position and rotation.
- Rectangle geometry is rendered from its local corners; other supported point
  geometry is emitted as a polyline.
- Body labels, liaison symbols and labels, and a ground marker are included. Ground
  and joint symbols respect planar orientation.
- Text and IDs are XML-escaped. Missing geometry body references fail explicitly.
- Bounds include rendered geometry and annotations, with a non-zero minimum image
  size and padding.

PNG export renders that SVG through a browser image and canvas at 2x scale. Invalid
SVG dimensions, unavailable browser canvas support, failed image decode/encode, and
dimensions beyond the configured `8192` pixel edge / `32,000,000` pixel area limits
are explicit errors. Temporary object URLs and download links are cleaned up.

JSON v3.0 remains the editable and reopenable document format; SVG/PNG exports are
visual artifacts only.

## Verification

The implementation was verified with 40 Vitest tests across 4 test files,
TypeScript, ESLint, a production build, and both development and production npm
audits. The suite covers empty and connected graphs, disconnected components,
isolated bodies, parallel edges, open and closed chains, multiple independent
cycles, the slider-crank and four-bar examples, deterministic layout, document
round trips, store lifecycle, SVG bounds and transforms, and PNG dimension guards.

Browser checks against the Vite development server verified Graph and Split
rendering, cross-view selection and inspector synchronization, graph-node removal
and undo, dirty new/open behavior, and actual toolbar-generated SVG, PNG, and JSON
Blobs. The captured JSON content was re-imported through the application's file
input and structurally compared after another save. See
[`TEST_RESULTS.md`](./TEST_RESULTS.md) for the measured evidence and limitations.

## Remaining limitations and next work

- The graph provides topology analysis only. It does not compute mobility,
  hyperstaticity, geometric closure, or mechanism motion.
- 3D editing, solving, animation, and formal certification of standardized symbols
  are out of scope.
- Graph positions and camera state are transient, not saved in the JSON document.
- Browser validation used the development server and Blob capture; OS-managed
  download-file capture and deployed-site behavior were not independently tested
  in this v0.2 run.
- `package.json` remains at `0.1.0`; a v0.2 release version, tag, or commit has not
  been created.
