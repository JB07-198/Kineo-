# Kineo v0.0 — Foundation

## Implemented

- Replaced the divergent legacy document/store shape with the canonical JSON v3.0
  model: metadata, joint-definition catalogue, equivalence classes, liaison instances,
  kinematics block and geometry entities.
- Kept valid v3.0 documents lossless across Zod validation, model conversion, JSON
  serialization and reopening. Object schemas preserve unknown nested properties.
- Added runtime checks for finite numeric values, duplicate entity/DOF identifiers,
  unknown class and parent references, self-connected joints, invalid joint types,
  geometry ownership and driven-DOF references.
- Wired validated import and JSON download into the existing application header.
  Invalid imports report an error and leave the active document unchanged.
- Reworked Zustand document actions around the canonical model. Body deletion cascades
  to dependent liaisons and geometry, removes driven-DOF references, and clears child
  parent links. Joint deletion clears its driven-DOF references; the ground is protected.
- Added bounded undo/redo history for document edits and stable project scripts for
  type-checking, lint, Vitest and production build. Added a GitHub Actions CI workflow.
- Added Vitest tests that load the original JSON example directly from
  `documentation_etape1_etape2.txt`; no developer-specific filesystem path is used.

The v0.1 planar editor stores optional `position` and `rotation` fields on classes as
passthrough extensions. Their absence in existing v3.0 files remains valid; all
unrecognized existing fields are retained by validation and conversion.

## Tested

The current test run is documented in [`TEST_RESULTS.md`](./TEST_RESULTS.md). It
covers validation of the original specification, lossless serialization/reopening,
reference failures, safe store edits, cascades, and undo/redo. TypeScript, ESLint, and
the production build are run in CI and locally.

## Remaining

- There is no autosave or browser-local persistence; use the JSON download and open
  controls to save and reopen files.
- Standalone anchors are not top-level JSON entities in v3.0; attachment frames are
  stored on each liaison instance.
- Schema validation enforces JSON structure and references, not physical mechanism
  solvability or a computed mobility/hyperstatism.
